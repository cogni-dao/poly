# Paper-Trade Diff Analysis

> Operator-node note: the paper sidecar source/build/base manifest live in this repo; deployed sidecar wiring, env values, and candidate/preview/prod exposure are operator-owned. Paper validation must prove the flighted deployment, not just a local sidecar.

## Goal

**Paper trading must produce the same decisions as live trading on the same algorithm, so we can A/B copy-trade configs without burning real USDC.** Every divergence between a flighted paper tenant (`mode=paper`) and live on the same target wallet is either (a) a paper-fidelity bug worth fixing, (b) a deploy/wiring mismatch, or (c) a known irreducible ceiling worth documenting. The diff is the only honest signal — synthetic confidence is not.

**v0 trust contract**: a trust-twin tenant on a flighted non-production environment running the exact live config must track live daily PnL within +/-5% over a rolling 7d window before any experimental config gets promoted.

> Naming: the **skill** is `/paper-trade-diff-analysis` (the workflow / analysis loop); the **tool** is `scripts/paper-twin-diff.ts` (the per-run data + HTML report builder). Same separation as `/delta-minimizer` ↔ `poly-mirror-report`.

**Tool availability:** if `scripts/paper-twin-diff.ts` is absent in this node repo, file/execute the node-owned port of that tool first. Do not substitute a synthetic comparison or local-only sidecar smoke for paper fidelity proof.

## The workflow (4 steps, in order)

### 1 · Run the tool

```bash
PAPER_TWIN_DIFF_SINCE=<twin-registration-time-ISO> \
  pnpm tsx scripts/paper-twin-diff.ts
```

Reads explicit paper/live tenant config from the current operator-backed environment. Do not synthesize tenant credentials locally. Writes a timestamped subdir:

```
research/paper-twin-diff/<iso-utc>/
  report.html       ← human-facing. KPI cards (twin / live / Δ), bucket strip
                      (both_open / twin_only / live_only / both_closed),
                      per-market table sorted by |Δ realized $|, TAKEAWAY placeholder.
  bundle.json       ← AI read surface. Full twin + live responses, diff array,
                      window echo.
  findings.json     ← empty stub. YOU fill it in step 3.
```

Always set `PAPER_TWIN_DIFF_SINCE` to the trust-twin registration time. Without it the diff is dominated by live pre-twin history — the twin physically couldn't have mirrored those fills, so a structurally pessimistic number is guaranteed and the comparison is meaningless. Get the canonical timestamp from the operator-provided tenant config or online work item.

The tool is read-only — no DB writes, no orders placed.

### 2 · Cross-reference code BEFORE bucketing anything

Findings claim something about behavior. That claim must be grounded in code. Cite `file:line`:

- **Twin under-fills vs live (paper-fidelity)** → `sidecars/paper-trader/vendor/pm_trader/pm_trader/engine.py` (maker-fill loop, Data-API lag, queue position), `sidecars/paper-trader/server.py` (filled_size_usdc convention, fill loop).
- **Twin over-fills vs live (structural ceiling)** → engine.py queue model; the OSS engine inherently overstates when our limit price is at the target's queue-leader level.
- **Same algo, different decisions (algorithm divergence)** → `app/src/features/copy-trade/plan-mirror.ts` (the pure planner). This is the bug class the diff exists to surface.
- **Twin missing a market live had (state mismatch)** → expected when live had a position pre-T0; follow-up branches (`layer`, `hedge`, `sell_close`) in `plan-mirror.ts` only fire when local position exists.
- **Realized $ inflated equally on both sides (v0 hardcode)** → `sidecars/paper-trader/server.py` `filled_size_usdc = intent.size_usdc` v0 convention; not a bug per se, but inflates the diff number predictably.

If you say "twin underfilling" without naming a file:line in the sidecar OR the planner, you haven't done the work.

### 3 · Author the takeaway + findings.json

Categorize each material divergence (use the bundle's `diffs` array, top by |Δ realized $|) into one of four buckets:

| Bucket                   | Definition                                                                                             | Next action                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------- |
| **paper-fidelity bug**   | Twin under-fills due to a sidecar mechanic (Data-API lag, ephemeral SQLite reset, partial-fill drift). | File `task.*` / `bug.*` — fix in sidecar / overlay.                                               |
| **structural ceiling**   | Queue position not modeled. Irreducible ~2-4% gap.                                                     | Document, do NOT "fix" — it's by design under the OSS-only constraint.                            |
| **algorithm divergence** | Same algo, different decisions on the same target fill.                                                | Pick one market → run [`/delta-minimizer`](../delta-minimizer/SKILL.md) on it for per-market RCA. |
| **state mismatch**       | Live had a pre-T0 position the twin didn't, so follow-up branches diverged.                            | Expected for first 2-4 weeks; converges as pre-T0 markets resolve.                                |

Edit `findings.json` in the timestamped dir — fill `bucket_breakdown`, `primary_class`, `primary_confidence` (0-100), `primary_one_liner`, optional `secondary_*`, `recommended_next_fix`, `authored_at` (ISO).

Then edit `report.html` between `<!-- TAKEAWAY:START -->` and `<!-- TAKEAWAY:END -->` to render the headline finding for the human reader. Mirror delta-minimizer's takeaway style: one Top Finding + confidence %, optional secondary, then a single Pareto next-fix paragraph.

### 4 · Commit + (optional) re-render scorecard

Commit the entire timestamped dir to git on the analysis branch. History matters — diff reports are durable artifacts the next agent reads to spot trends.

If a finding warrants a knowledge entry (e.g., a confirmed paper-fidelity bug class), also write `docs/research/<date>-paper-twin-<topic>.md` per the [`/data-research`](../data-research/SKILL.md) persistence convention (`type: scorecard`, `domain: paper_twin`, `confidence_pct: <your authored value>`). Link the report.html path from inside the markdown. Don't duplicate the matrix — link to the HTML.

## What the tool DOES (so you know what NOT to redo)

- Pulls paper/live base URLs from explicit env/config supplied by the current operator-backed environment. Do not hard-code preview/prod assumptions if the operator has flighted a different validation slot.
- Both calls hit `GET /api/v1/poly/research/copy-trade-pnl?billing_account_id=…&mode=paper|live[&since=…&until=…]`.
- Joins on `market_id`, sorts by `|realized_diff_usdc|` desc.
- Emits the 4 position-state buckets via `has_open_position` (which mirrors the executor's `DEDUPE_AT_DB` predicate — so "both_open" means both tenants have an active resting-or-open-position slot on that market).
- Sets `TAKEAWAY:START/END` markers — your inject point.
- Echoes `since` / `until` in the response and in the HTML window banner; loud warning if `SINCE` is unset.
